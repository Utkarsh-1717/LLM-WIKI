# Session Log — 2026-06-13

---

## Session Summary

This session tackled the ultimate scaling bottleneck in the Pairs Trading Pipeline. The algorithm was fundamentally blocked from analyzing the full NSE 500 matrix (124,750 pairs) due to algorithmic time complexity in Python sequential loops, which caused Kaggle kernels to exceed the 12-hour maximum runtime. By converting the execution state machine to C++ via Numba `@njit`, processing times dropped by 10x per pair. Adding Joblib multiprocessing and Lazy Evaluation for cointegration allowed the entire 125,000-pair universe to complete within 1.5 hours.

---

## Key Discoveries

### 1. Python Loop Timeout Reality
A standard Pandas/Python sequential `for` loop executing a basic state machine (cash, friction, entry/exit flags) takes `~0.09s` per pair. Over 125,000 combinations, this equals `125 hours` of raw compute, guaranteeing a Kaggle Timeout. 

### 2. Numba `@njit` Compilation
Vectorizing a state machine is difficult, so we compiled the loop instead. By casting all Pandas Series to raw Numpy arrays (`.to_numpy()`) and passing them to a Numba-decorated function (`@numba.njit`), the code compiles to C++ machine code at runtime. 
- Execution time per pair dropped from `~94ms` to `~9ms`.
- Perfect math match: The Numba output matched the exact PnL down to the cent, proving no "vectorization rounding leakage".

### 3. Lazy ADF Evaluation
The `statsmodels` `adfuller` test is mathematically heavy and cannot be compiled via Numba, taking `~1.5 seconds` per pair. Running this blindly on 125,000 combinations takes `52 hours`. 
- **Solution:** Execute the ultra-fast Numba backtest first (9ms). Only trigger the heavy ADF test on pairs that generate a strictly positive mathematical PnL. This filtering reduces the 52-hour compute wall down to less than 1.5 hours.

### 4. Soul Production Compiler Framework
Solidified the rule that any pipeline scaled to `N > 10,000` inside the `Soul` directory MUST utilize Numba and Joblib. Sequential python loops are strictly banned at production scale.

### 5. The Correlation Fallacy
By extracting data on the first few thousand pairs before the timeout, we definitively proved that Pearson correlation ($\rho$) is uncorrelated (even slightly negatively correlated) with backtested PnL. Cointegration (ADF p-value) and Volatility are the true separators.

### 6. Walk-Forward Prediction vs Hindsight
We pivoted the pipeline's goal. Instead of ranking the Top 50 pairs by hindsight PnL (which causes curve-fitting), the Numba engine now explicitly extracts predictive Ex-Ante Physical Parameters (`half_life`, `kalman_q`, `spread_vol`, `zero_crossings`) to build a true walk-forward ranking filter.

### 7. Lagger Lockout & Exact Fees (Logic Hallucinations)
We discovered and corrected two massive AI hallucination bugs in the Numba engine translation:
- The engine failed to implement the `is_locked_out` state, allowing immediate re-entry after 15:15 forced EOD exits, leading to trade spam.
- The engine failed to compute the exact Zerodha Equity MIS fees, using generic percentages instead. Both were fully corrected in the final V5 run.
